# 사용자 리서치 방법 레지스트리

이 디렉토리는 "User Research Module"이 사용하는 **플러그인식 리서치 방법 목록**입니다.
파일 하나 = 방법 하나. 새 방법을 추가하고 싶으면 이 디렉토리에 마크다운 파일을 하나 추가하면 됩니다 (코드 수정 불필요).

## 현재 등록된 방법

| 파일 | id | mode | 용도 |
|---|---|---|---|
| `quick-persona-check.md` | quick-persona-check | quick | 일상적인 사용자 대면 산출물에 자동 부착되는 기본 반응 예측 |
| `deep-customer-insight.md` | deep-customer-insight | deep | 신제품 기획·포지셔닝 변경 등 중대 의사결정을 위한 4-PHASE 심층 분석 |
| `staged-insight-research.md` | staged-insight-research | staged | 1차 광범위 조사→2차 확장→3차 포커스 인터뷰를 프로젝트 단위로 축적 저장, 후속 작업이 이어받는 단계형 리서치 |

## 새 방법을 추가하는 법

1. 이 디렉토리에 `[method-id].md` 파일을 만든다.
2. 파일 맨 위에 다음 헤더를 포함한다 (YAML 문법은 아니지만 형식을 통일):

```markdown
# 방법: [method-id]

- id: [method-id]
- name: [사람이 읽는 이름 (한국어)]
- mode: quick | deep | realuser | (새 태그도 가능)
- when-to-use: [언제 이 방법을 골라야 하는지 한 줄]
```

3. 그 아래 본문에 실제 작업 지시(단계, 산출물 형식, 가드레일)를 작성한다.
4. **가상 페르소나를 사용하는 방법이라면** "본 결과는 가상 페르소나 시뮬레이션입니다..." 디스클레이머를 반드시 포함한다. 실사용자 데이터 기반 방법(예: 실사용자 인터뷰 녹취 분석)은 이 디스클레이머가 필요 없다 — 대신 데이터 출처를 명시한다.
5. `config/skill-templates/user-researcher.md`나 다른 코드를 수정할 필요는 없다. user-researcher 알바가 이 디렉토리를 스캔해서 자동으로 방법을 찾는다.

## 추후 보강 계획 (placeholder)

다음 방법들은 아직 만들어지지 않았지만, 향후 이 레지스트리에 파일로 추가될 예정입니다:

- **실사용자 다이어리 스터디** (`realuser` 모드 예정) — 실제 사용자가 일정 기간 사용 기록을 남기는 방식. 가상 시뮬레이션이 아니므로 디스클레이머 대신 참여자 수·기간을 명시하는 방식으로 설계될 것.
- **텔레메트리 분석** — 실제 서비스 로그/이벤트 데이터를 기반으로 한 정량 사용자 행동 분석. 정성적 페르소나 방법과 결합해 사용할 수 있음.

이 방법들이 필요하면 위 "새 방법을 추가하는 법"을 따라 파일을 만들면 됩니다.
