# 5단 보고 형식

코드·시스템 변경 작업의 최종 보고에 반드시 적용한다.

## 5단 형식

| 단계 | 항목 | 규칙 |
|------|------|------|
| 1 | **원인** | 실제로 뭐가 왜 잘못됐나. 추측이면 "guess" 표시 |
| 2 | **수정** | 건드린 파일/라인 목록 (`path:line` 형식) |
| 3 | **재발방지** | 근본 원인 수정 / 가드레일 / 회귀 테스트 중 최소 1개. 핫픽스면 "의도적 생략 (사유)" |
| 4 | **검증** | 실제 실행한 명령과 결과만. 미실행은 "not run" 또는 "검증 불가 (사유)" |
| 5 | **남은리스크** | 회귀 가능성·미검증 영역만. 없으면 "해당 없음" |

## 적용 범위

- 코드 변경, 설정 수정, 시스템 조작 → **반드시 5단 보고**
- 단순 조사·질의·읽기 작업 → 생략 가능

## 검증 화이트리스트 (검증 불가 인정)

다음 항목은 별도 사유 없이 "검증 불가"로 인정한다:
- dev 서버 기동
- 유료 API 실호출
- 실 렌더/실 배포
- 브라우저 e2e

이 외 검증 불가 항목은 **구체 사유 필수**.

## 남은 리스크 규칙

- "더 좋게 만들 수 있음" 류 wishlist 금지
- 회귀 위험·미검증 부분만 기록
- 진짜 없으면 "해당 없음"

## 예시

```markdown
### 1. 원인
`routes.ts:42`에서 `/api/video` 라우트가 누락됨.

### 2. 수정
- `src/routes.ts:42` — 라우트 추가

### 3. 재발방지
라우트 등록 누락은 tsc가 잡지 못함 → 통합 테스트 추가 예정.

### 4. 검증
`npx tsc --noEmit` → EXIT=0

### 5. 남은 리스크
해당 없음.
```
