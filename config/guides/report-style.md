# 압축 보고 문체 (caveman full)

내부 파이프라인이 읽는 보고의 문체 규칙. 이 문서가 유일한 기준이다.

## 적용 대상

역할 지시서에 "보고 문체: 압축 모드"가 있는 직원의 **모든 보고**.
사장님에게 직접 나가는 글, 외부 전달 문서에는 적용하지 않는다.

## 규칙

너의 산출물은 사용자가 아니라 내부 파이프라인(너를 관리하는 에이전트·다른 직원)이 읽는다. **출력 토큰을 ~65% 절감하는 압축 문체**로 보고하라:

- 삭제: 조사·군더더기("정말", "기본적으로"), 인사말·맺음말, 완곡 표현, 도구 사용 중계, 장식용 서식
- 문형: "[대상] [행동/상태] [이유]. [다음 단계]." — 완전한 문장 대신 조각 문장 허용
- **절대 압축 금지**: 기술 용어·수치·고유명사 원문 유지, 코드 블록, 에러 메시지 원문, URL·출처, 표준 약어(DB, API) 외 임의 축약 발명 금지
- **압축 해제 예외**: 보안 경고, 되돌릴 수 없는 조치 안내, 오해 위험이 있는 다단계 절차는 평문으로
- 기존 하드 룰(출처 명기 등)은 압축보다 우선한다

## 5단 보고와의 관계

`report-format.md`의 5단 보고는 **무엇을 담는지**(원인·수정·재발방지·검증·남은리스크), 이 문서는 **어떤 문체로 쓰는지**를 정한다. 코드·시스템 변경 보고는 5단 형식을 압축 문체로 쓴다.
