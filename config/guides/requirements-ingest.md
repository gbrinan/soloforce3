# 요구사항 인제스트 — 이 일에만 있는 게이트

공통 게이트(정산·역추적·미상·원본 읽기전용·민감 판정·3회 격리)는 `config/guides/corpus-gates.md`에 있다.
변환 이상 증상은 `config/guides/ingest-pitfalls.md`에서 찾는다. **여기 다시 적지 않는다.**

이 문서에는 요구사항(10-requirements) 인제스트에만 해당하는 것만 남긴다.

## 버킷 (정산 이름)

발견 = **처리**(신규·내용변경) + **미처리**(대체됨·동일사본·변경없음·건너뜀). 버킷별 건수를 보고에 적는다.
대상 판정은 서버가 계산해 작업 지시에 실어 보낸다 — 스스로 다시 세지 말고 **받은 목록과 실제 처리 결과가 맞는지**를 센다.

## 산출물은 두 개뿐이다

1. `10-requirements/requirements.md` — 정규화된 단일 진실(SSOT)
2. `10-requirements/_changelog.md` — 변경 1줄 (날짜·주체·유형·내용·근거 원본)

원본(raw/)은 건드리지 않는다. 새 원본이 왔다고 옛 원본을 지우거나 덮지 않는다.

## 요구사항 전용 게이트

**미확정을 확정으로 만들지 않는다.** 후보가 여럿인 일정("9/10·17·29 중 1일")은 하나로 고르지 않고
후보 그대로 적는다. 정원·난이도처럼 원문에 없는 값은 `미정 — 협의 필요`로 남긴다.
공통 게이트의 `미상` 규칙을 요구사항에서 부르는 이름이 `미정`이다(이유는 그쪽에 있다).

**빠진 것을 목록으로 만든다.** 정규화하면서 "원문에 없어서 못 채운 항목"은 `openIssues`에 모은다.
요구사항 문서의 가치는 적힌 것보다 **무엇이 아직 안 정해졌는지**에 있다.

**출처를 값 옆에 남긴다.** 표의 각 행에 어느 원본에서 온 값인지 적는다(공통 게이트의 역추적을
요구사항에서는 "표의 출처 열"로 구현한다).

**타입별 정규화 스키마를 따른다.**
- 교육: 과정명·난이도·총시간·정원 / 차수별(내용·시간·일자·확정여부) / 모듈(세부내용·학습목표·시간·실습) / 멘토링(조수·조별시간·플랫폼) / 장소
- 컨설팅: 과제명·범위 / As-Is 프로세스·페인(정량) / To-Be 목표 / 가용 데이터·보안 제약 / 마일스톤 / 기대 산출물

**변경분만 고친다.** `revised`로 온 원본은 requirements.md 전체를 다시 쓰지 말고 달라진 부분만
갱신한다. 사람이 손댄 문장을 재생성으로 날리지 않는다.

## 끝난 뒤

`project.json`의 `openIssues`를 갱신하고, 확정 일정이 생겼으면 `status`를 올린다.
`currentVersion`은 건드리지 않는다 — 그건 산출물(40-deliverable) 승인의 몫이다.
