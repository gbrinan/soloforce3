# 이력서 & 친구 역량 매칭 (resume-matching)

명함(연락처)과 별개로, 친구의 **역량(이력/스킬/경력)** 을 다루고 작업에 **적합한 친구를 찾는** 기능.

## 두 레이어 구분
- **명함** = `partners.json` (회사·담당자·연락처·토큰). 친구 추가 시 자동 교환.
- **이력서** = `history/external/resumes/*.md` (스킬·경력·프로젝트). **선택적 공유(옵트인)**.

```
history/external/resumes/
├── _index.md     ← 가벼운 명단 (친구당 1줄: 이름 + 한줄 요약, <!--pid:id--> 키)
├── me.md         ← 내({{USER}}) 이력서 — "나에 대한 모든 것"
└── <id>.md       ← 친구별 이력서 (친구가 공유한 것 자동 저장)
```

## 1. 내 이력서 작성·수정 ({{USER}} 경력을 말로 줄 때)
{{USER}}이 자기 **경력·스킬·프로젝트·이력**을 말하면 → `history/external/resumes/me.md`를 **SafeWrite로 갱신/추가**한다.
- 처음이면 `# 이름 (회사/부서)` → `## 소개` → `## 스킬` → `## 경력` → `## 프로젝트` 구조로 작성.
- 기존 내용이 있으면 SafeRead로 읽고 해당 섹션에 **추가/수정** (통째로 덮어쓰지 말 것).
- ⚠️ me.md 쓰기는 **승인 카드**가 뜰 수 있음(마이크루 쓰기 보안모델) — 정상이니 {{USER}}께 승인 요청.
- {{USER}}이 직접 편집하려면 **친구 탭 → "이력서 편집"** 버튼도 있음.
- 갱신 후, **이력서를 공유 중인 친구**(partners.json `resumeSharedAt` 있는 친구)가 있으면 "업데이트된 이력서를 재공유할까요?" 안내.

## 2. 이력서 공유 (옵트인)
- 친구 추가 시 "이력서 포함" 체크, 또는 친구 탭에서 **이력서 공유 토글**, 또는 일괄 발송.
- 공유 ON → `resumeSharedAt` 세팅 + me.md 발송. OFF → 조용히 해제(상대 알림 없음, 이미 보낸 건 회수 불가).
- 친구가 보낸 이력서는 **자동으로** `resumes/<id>.md` 저장 + `_index.md` 갱신 + 시스템 알림.

## 3. 작업에 적합한 친구 매칭 ★ 핵심
{{USER}}이 **"이 작업 누구한테 맡길까 / 적합한 친구 찾아줘"** 라고 하면:

1. **매칭 알바(Agent)에 위임** — 직접 다 읽지 말고 알바를 띄운다. (이력서 원문이 마이크루 컨텍스트에 쌓이는 비용 방지)
2. 알바가 **2단계로** 읽는다:
   - 1단계: `history/external/resumes/_index.md`만 읽어 **후보 2~3명** 추림 (명단은 가벼움)
   - 2단계: 추린 후보의 `<id>.md`만 읽어 작업 요건과 대조
3. 알바가 **추천 + 근거**(왜 이 친구가 적합한지)만 반환 → 마이크루는 결론만 {{USER}}에게 전달.

- ⚠️ 비용 원칙: **모든 이력서를 통째로 읽지 말 것.** 반드시 `_index` → 후보 순.
- 알바가 파일을 못 읽는 경우엔 마이크루가 직접 `_index.md`만 읽고 후보를 좁힌 뒤 후보 이력서만 확인.
- `<id>.md`/me.md 머리글에 회사·담당자가 있어 파일이 스스로 누군지 설명함(id↔이름 매핑 불필요).
