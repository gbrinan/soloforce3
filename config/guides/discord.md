# 디스코드 연동

## 개요
디스코드 봇을 통해 사장님이 디스코드에서도 지니를 지휘하고 답변을 받을 수 있는 기능.
텔레그램 브릿지(`config/guides/telegram.md`)와 완전히 동일한 구조(페어링-바이-디폴트, 보조 AI 트리아지, 승인 버튼)를 공유한다.
Gateway(WebSocket, discord.js) 방식으로 동작하며 텔레그램의 long polling과 달리 상시 연결을 유지한다.

## 봇 만들기 (최초 1회, 사장님이 직접 수행해야 함)

1. [Discord Developer Portal](https://discord.com/developers/applications) 접속 → **New Application** → 이름 입력(예: mycrew)
2. 좌측 메뉴 **Bot** 탭 → **Reset Token**(최초 1회는 바로 토큰 표시) → 토큰 복사 (`.env`에 넣을 값)
3. 같은 Bot 탭에서 **Privileged Gateway Intents** 섹션의 **MESSAGE CONTENT INTENT**를 반드시 켠다
   - ⚠️ 이 옵션이 꺼져 있으면 봇이 메시지 내용을 아예 읽지 못해 모든 명령/대화가 무시된다.
4. 좌측 메뉴 **OAuth2 → URL Generator**
   - **SCOPES**: `bot` 체크
   - **BOT PERMISSIONS**: `Send Messages`, `Read Message History`, `View Channel`, `Use External Emojis`(선택), `Attach Files`(선택)
   - 하단에 생성된 URL을 브라우저에서 열어 원하는 서버에 봇을 초대

## .env 설정

프로젝트 루트의 `.env` 파일에 아래 한 줄을 추가한다 (없으면 `.env.example`을 복사해서 생성):

```
DISCORD_BOT_TOKEN=발급받은-토큰
```

- 이 값이 비어 있으면 디스코드 브릿지는 자동으로 비활성 상태를 유지한다 (서버는 정상 동작).
- `.env`는 `.gitignore`에 포함되어 있어 커밋되지 않는다.
- 설정 후 mycrew 서버를 재시작해야 브릿지가 시작된다.

## 페어링 방법 (최초 1회)

디스코드도 텔레그램과 동일하게 "페어링-바이-디폴트" 방식이다. 어떤 채널/DM도 먼저 등록하지 않으면 아무 권한이 없다.

1. 초대한 서버의 채널(또는 봇에게 DM)에서 아무 메시지나 전송 (또는 `/start`)
2. 봇이 "이 채널/DM은 페어링된 경우만 사용할 수 있습니다..." 안내와 함께 6자리 코드를 요구
3. mycrew 콘솔 로그 또는 지니 채팅창에 표시된 6자리 코드를 확인
4. 디스코드에서 `/pair 123456` 형식으로 전송 (실제 코드로 치환)
5. "✅ 페어링 완료" 응답을 받으면 이후부터 자유롭게 지니에게 메시지 전송 가능

페어링 코드는 10분간 유효하며, 1회용이다. 5회 연속 틀리면 해당 채널은 15분간 잠금된다.
여러 채널(서버 채널·DM)을 각각 페어링할 수 있다. 각 채널은 개별적으로 페어링 절차를 거쳐야 한다.
텔레그램과 디스코드는 완전히 독립된 페어링 상태(`history/discord.json` vs `history/telegram.json`)를 가진다 — 서로 영향 없음.

## 명령어 목록

| 명령어 | 설명 |
|--------|------|
| `/start` | 안내 메시지 (미페어링 시 코드 발급 안내) |
| `/pair <code>` | 페어링 코드로 등록 |
| `/unpair` | 현재 채널의 페어링 해제 |
| `/status` | 서버 가동시간, 진행 중인 작업 수 확인 |
| `/help` | 명령어 목록 표시 |
| (그 외 일반 텍스트) | 페어링된 경우 지니에게 그대로 전달, 지니가 답변 |

이 명령어들은 슬래시커맨드(디스코드 네이티브 `/` 자동완성)가 아니라 일반 텍스트 메시지로 처리된다 — 텔레그램과 동일한 방식이라 봇을 애플리케이션 커맨드로 별도 등록할 필요가 없다.

## 동작 방식 (참고)

- 페어링된 채널이 보낸 메시지는 `[디스코드] ...` 형태로 지니에게 전달되며, 사장님의 직접 지시로 취급된다.
- 지니의 답변은 `[REPLY_TO_DISCORD channelId=...]` 마커로 감싸져 자동으로 해당 채널에 전송된다.
- 2000자를 넘는 응답은 여러 메시지로 자동 분할되어 전송된다 (디스코드 메시지 길이 제한).
- 보조 AI 트리아지(Gemini Flash)는 텔레그램·데스크톱과 완전히 동일한 로직을 공유한다 — `GEMINI_API_KEY` 설정 시 자동 활성화.
- 봇 자신 또는 다른 봇이 보낸 메시지는 무시한다 (무한루프 방지).

## 디스코드에서 승인/거부 버튼으로 바로 처리 가능

MCP 도구가 readPaths 밖 경로에 접근하는 등 사장님 승인이 필요한 요청이 발생하면, 대시보드 알림뿐 아니라 디스코드 메시지에도 **✅ 승인 / ❌ 거부** 버튼(네이티브 Message Component)이 함께 도착한다.

- 버튼은 **페어링된 채널에만** 발송·응답된다. 미페어링 채널에서 버튼을 눌러도 "권한 없음" 안내만 표시되고 아무 것도 처리되지 않는다.
- 버튼을 누르면 대시보드/텔레그램의 승인·거부와 **완전히 동일한 처리 경로**(`resolveApproval`)를 거친다.
- 처리 후에는 해당 메시지의 버튼이 사라지고 처리 결과가 반영된다.
- 대시보드/텔레그램 등 다른 경로에서 먼저 처리된 뒤 디스코드 버튼을 누르면 "이미 처리됨" 안내만 표시되고 안전하게 무시된다.

## 보안 주의사항

- **토큰 노출 시**: Discord Developer Portal → Bot → **Reset Token**으로 즉시 토큰을 재발급하고 `.env`를 갱신한다.
- 토큰은 코드에 절대 하드코딩되지 않으며 `process.env.DISCORD_BOT_TOKEN`으로만 읽는다.
- 미페어링 채널은 어떤 지시도 지니에게 전달되지 않는다.
- 페어링된 채널이라도 분당 20건을 초과하는 메시지는 차단되고 경고 1회만 발송된다.
- 디스코드 채널/유저 ID(스노우플레이크)는 64비트 정수라 JS `number`로 다루면 정밀도가 손실된다 — mycrew는 항상 문자열로 저장·비교한다.

## 제한사항

- v1은 텍스트 메시지만 지원한다 (첨부파일/이미지는 무시됨).
- 슬래시커맨드(디스코드 애플리케이션 커맨드) 등록 없이 일반 텍스트 명령만 지원한다.
