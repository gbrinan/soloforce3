# 텔레그램 연동

## 개요
텔레그램 봇(@anan_cowork_bot)을 통해 사장님이 외부에서도 지니를 지휘하고 답변을 받을 수 있는 기능.
long polling 방식(서버가 텔레그램 서버에 주기적으로 요청)으로 동작하며, 별도의 외부 URL/포트 개방이 필요 없다.

## 봇 만들기 (이미 완료됨)

봇은 이미 텔레그램 @BotFather를 통해 생성되어 있다: `@anan_cowork_bot`.
새로 만들거나 재발급이 필요하면:

1. 텔레그램에서 `@BotFather`와 대화 시작
2. `/newbot` 전송 → 봇 이름 입력 → 봇 username 입력(반드시 `bot`으로 끝나야 함)
3. 발급된 토큰(`123456:ABC-DEF...` 형식)을 복사

## .env 설정

프로젝트 루트의 `.env` 파일에 아래 한 줄을 추가한다 (없으면 `.env.example`을 복사해서 생성):

```
TELEGRAM_BOT_TOKEN=발급받은-토큰
```

- 이 값이 비어 있으면 텔레그램 브릿지는 자동으로 비활성 상태를 유지한다 (서버는 정상 동작).
- `.env`는 `.gitignore`에 포함되어 있어 커밋되지 않는다.
- 설정 후 mycrew 서버를 재시작해야 브릿지가 시작된다.

## 페어링 방법 (최초 1회)

텔레그램은 "페어링-바이-디폴트" 방식이다. 즉, 어떤 텔레그램 chat도 먼저 등록하지 않으면 아무 권한이 없다.

1. 텔레그램에서 `@anan_cowork_bot`과 대화를 시작하고 아무 메시지나 전송 (또는 `/start`)
2. 봇이 "페어링된 사용자만 사용할 수 있습니다..." 안내와 함께 6자리 코드를 요구
3. mycrew 콘솔 로그 또는 지니 채팅창에 표시된 6자리 코드를 확인
4. 텔레그램으로 `/pair 123456` 형식으로 전송 (실제 코드로 치환)
5. "✅ 페어링 완료" 응답을 받으면 이후부터 자유롭게 지니에게 메시지 전송 가능

페어링 코드는 10분간 유효하며, 1회용이다. 5회 연속 틀리면 해당 chat은 15분간 잠금된다.

여러 텔레그램 계정(chat)을 각각 페어링할 수 있다. 각 chat은 개별적으로 페어링 절차를 거쳐야 한다.

## 명령어 목록

| 명령어 | 설명 |
|--------|------|
| `/start` | 안내 메시지 (미페어링 시 코드 발급 안내) |
| `/pair <code>` | 페어링 코드로 등록 |
| `/unpair` | 현재 chat의 페어링 해제 |
| `/status` | 서버 가동시간, 진행 중인 작업 수 확인 |
| `/help` | 명령어 목록 표시 |
| (그 외 일반 텍스트) | 페어링된 경우 지니에게 그대로 전달, 지니가 답변 |

## 동작 방식 (참고)

- 페어링된 chat이 보낸 메시지는 `[텔레그램] ...` 형태로 지니에게 전달되며, 사장님의 직접 지시로 취급된다.
- 지니의 답변은 `[REPLY_TO_TELEGRAM chatId=...]` 마커로 감싸져 자동으로 해당 텔레그램 chat에 전송된다.
- 4096자를 넘는 응답은 여러 메시지로 자동 분할되어 전송된다.
- 마크다운 서식은 적용되지 않는다 (일반 텍스트로 전송 — 서식 파싱 오류 방지 목적).

## 텔레그램에서 승인/거부 버튼으로 바로 처리 가능 (부재중 운영 완성)

MCP 도구가 readPaths 밖 경로에 접근하는 등 사장님 승인이 필요한 요청이 발생하면, 대시보드 알림뿐 아니라 텔레그램 메시지에도 **✅ 승인 / ❌ 거부** 인라인 버튼이 함께 도착한다. 데스크톱 대시보드를 열지 않고도 텔레그램에서 바로 처리할 수 있다.

- 버튼은 **페어링된 사용자에게만** 발송·응답된다. 미페어링 chat이 어떻게든 버튼을 눌러도(예: 포워딩된 메시지) "권한 없음" 토스트만 표시되고 아무 것도 처리되지 않는다.
- 버튼을 누르면 대시보드의 승인/거부와 **완전히 동일한 처리 경로**(`resolveApproval`)를 거친다 — 캐시 정책, 반복 요청 자동 승인, 감사 로그 모두 동일하게 적용된다.
- 처리 후에는 해당 텔레그램 메시지가 "✅ 승인됨 / ❌ 거부됨 + 처리자 + 처리 시각"으로 자동 갱신되고 **버튼이 사라진다** (중복 클릭 방지).
- 대시보드 등 다른 경로에서 먼저 처리된 뒤 텔레그램 버튼을 누르면 "이미 처리됨" 토스트만 표시되고 안전하게 무시된다 (에러 없음).
- 승인 요청이 만료(20분 타임아웃)되었거나 존재하지 않는 경우에도 "요청을 찾을 수 없습니다" 토스트로 안전하게 처리된다.
- 텔레그램 메시지에는 사유/경로 등 대시보드와 동일한 정보가 표시되며, 버튼으로 처리 시 사유는 "텔레그램에서 사장님 승인/거부"로 고정 기록된다 (텔레그램 특성상 자유 텍스트 사유 입력은 지원하지 않음).

## 보안 주의사항

- **토큰 노출 시**: 텔레그램 `@BotFather`에서 `/revoke` 명령으로 즉시 토큰을 재발급하고 `.env`를 갱신한다.
- 토큰은 코드에 절대 하드코딩되지 않으며 `process.env.TELEGRAM_BOT_TOKEN`으로만 읽는다.
- 미페어링 chat은 어떤 지시도 지니에게 전달되지 않는다.
- 페어링된 chat이라도 분당 20건을 초과하는 메시지는 차단되고 경고 1회만 발송된다.

## 제한사항

- v1은 텍스트 메시지만 지원한다 (사진/파일 첨부는 무시됨).
- 마크다운 서식이 적용되지 않아 굵게/기울임 등은 일반 텍스트로 표시된다.
- 작업 완료/루프 완료 시 자동 알림(`sendTelegramNotice`)은 구현되어 있으나 아직 잡/루프 완료 이벤트에 연결되어 있지 않다 (TODO).
- long polling 특성상 다른 프로세스가 같은 봇 토큰으로 동시에 폴링 중이면(409 conflict) 자동으로 60초 대기 후 재시도한다.

## 관련 위치
- 구현: `src/server/telegram.ts` (승인 콜백 처리는 `handleCallbackQuery`, 승인 큐 연동은 `src/server/approvals.ts`)
- 페어링 데이터: `history/telegram.json`
- 서버 시작 연동: `src/server/index.ts`의 `startTelegramBridge()`
- 승인/거부 버튼 로직 테스트: `scripts/telegram-approval-test.ts` (네트워크 호출 없는 순수 로직 테스트)

## 무아난(muanan) 페르소나

텔레그램 답변은 "무아난" 페르소나로 동작합니다: 결론 먼저 + 반대 근거(counter-evidence) 제시, 판단에 필요한 맥락(수치·출처·전제) 명시, 결정 사안은 경우의 수 2~3개(장단점+권장안), 동의하지 않으면 정중한 반박. 단순 확인·인사는 짧게 답합니다.

## 보조 AI 트리아지 (비용 절감 레이어)

일반 대화는 무료 티어 Gemini Flash(`gemini-2.5-flash`)가 먼저 응답하고, 사장님의 개인 데이터·일정·작업·파일과 관련되거나 mycrew의 기억/도구/위임이 필요한 요청만 지니(Genie)에게 자동으로 승격됩니다.

### 동작 방식

- `.env`에 `GEMINI_API_KEY`가 설정되어 있으면 트리아지가 활성화됩니다. 미설정 시 트리아지는 완전히 비활성 상태를 유지하며, 기존과 동일하게 모든 메시지가 지니에게 직행합니다.
- 메시지가 도착하면 다음 순서로 판단합니다:
  1. `"지니야"`로 시작하거나 `/genie <내용>` 명령 → 항상 지니 직행 (접두사/명령은 제거 후 전달)
  2. mycrew 기능 키워드(위임·시켜·파일·작업·일정·기억·저장 등) 포함 → 지니 직행
  3. 그 외 → 보조 AI(무아난·Gemini Flash)가 먼저 응답 시도
- 보조 AI는 mycrew의 기억·파일·도구에 접근할 수 없습니다. 개인 데이터나 실제 작업 실행이 필요하다고 판단되면 스스로 지니에게 승격시킵니다.
- Gemini API 호출이 실패(타임아웃/네트워크 오류/쿼터 초과 등 어떤 사유든)하면 메시지를 버리지 않고 즉시 지니에게 전달합니다 (crash-safe fallback).

### 아이콘 의미

- 🤖 — 보조 AI(무아난·Gemini Flash)의 답변
- 🧞 — 지니(Genie)의 답변 (mycrew 기억·파일·도구 활용)

### 비용

- Gemini Flash는 무료 티어(`$0`) 범위에서 사용됩니다. 무료 키 발급: https://aistudio.google.com
- 개인 데이터가 포함된 요청이나 실제 작업 실행이 필요한 요청은 자동으로 지니에게 승격되어 처리되므로, 민감한 내용이 보조 AI에만 머물지 않습니다.

### 대화 맥락

보조 AI는 chat별로 최근 6턴(사용자/모델 교환)을 인메모리 링버퍼로 기억합니다. 지니에게 전달된 메시지는 모델 응답 턴을 만들지 않지만, "(지니에게 전달됨)" 메모로 히스토리에 남아 보조 AI가 대화 흐름을 참고할 수 있습니다. 서버 재시작 시 이 히스토리는 초기화됩니다 (영속 저장 없음).
