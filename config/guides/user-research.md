# 사용자 리서치 모듈 가이드

직원이 상세페이지, 광고 카피, 기획전, 제품 기획 같은 사용자 대면 산출물을 만들 때
**예상 사용자 반응**을 자동으로 붙여주는 모듈입니다.

## 모듈 소개

이 모듈이 있으면 직원이 카피나 기획을 만들 때마다 "실제로 사람들이 이걸 보면 어떻게 반응할까?"를
가상 페르소나로 시뮬레이션해서 보여줍니다. 별도로 "사용자 조사해줘"라고 요청하지 않아도,
산출물 성격에 따라 자동으로 붙습니다.

## 두 모드와 선택법

| 모드 | 언제 쓰나 | 산출물 분량 |
|---|---|---|
| **빠른 조사** (quick) | 일상적인 작업 — 상세페이지, 카피, 기획전 | 1~2페이지 |
| **심층 조사** (deep) | 신제품 기획, 포지셔닝 변경 같은 중대 결정 | 풀 리포트 (4-PHASE) |

### 선택하는 방법

- **"빠르게" / "간단히"**라고 말하면 → 빠른 조사
- **"깊게" / "제대로"**라고 말하면 → 심층 조사
- **아무 말 안 하면** → 마이크루가 자동으로 판단합니다.
  - 일상적인 작업(카피 한 줄, 상세페이지 하나)이면 빠른 조사를 기본으로 수행
  - 신제품 기획·포지셔닝 변경처럼 중대한 결정이면 심층 조사를 제안하고, 비용이 크다는 점을 안내한 뒤 진행 여부를 확인

## 자동 동작 조건

다음 산출물을 만들 때는 별도 요청 없이도 "예상 사용자 반응" 섹션이 자동으로 붙습니다:

- 상세페이지, 광고/마케팅 카피, 기획전
- 제품 기획, 포지셔닝
- UX 설계, 네이밍, 가격 정책

다음 키워드가 작업 지시에 포함되면 트리거로 인식됩니다:
페르소나, JTBD, LMF, 고객 인사이트, 타겟 고객, 소구점, 상세페이지, 기획전, 카피, 포지셔닝, 사용자 조사, UX.

## 추후 보강 계획

지금은 가상 페르소나 시뮬레이션만 지원합니다. 앞으로 다음이 추가될 예정입니다:

- **실사용자 다이어리 스터디**: 실제 사용자가 남긴 사용 기록을 분석하는 방법
- **텔레메트리 분석**: 실제 서비스 로그/이벤트 데이터 기반 정량 분석

새 방법은 `config/research-methods/`에 파일 하나만 추가하면 되는 구조라, 코드 수정 없이 확장됩니다.
자세한 추가 방법은 `config/research-methods/README.md` 참고.

## 한계 — 반드시 알아둘 것

가상 페르소나는 **시뮬레이션**입니다. 실제 사용자 데이터가 아닙니다.

- 신제품처럼 실제 데이터가 없는 경우엔 유용한 가설 도출 도구가 되지만, 실제 A/B 테스트나 사용자 인터뷰를 대체할 수 없습니다.
- 모든 결과 하단에 다음 문구가 자동으로 붙습니다: "본 결과는 가상 페르소나 시뮬레이션입니다. 실제 사용자 검증을 대체하지 않습니다."
- 중요한 의사결정(가격 정책, 대규모 캠페인 예산 집행 등)은 이 리포트만으로 확정하지 말고, 가능하면 실제 사용자 검증을 병행하세요.
