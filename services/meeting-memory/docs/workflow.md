# 사람과 자동화의 분담

Drive / 직접 업로드 → Groq 또는 Gemini Developer 전사 → Gemini 요약 → Markdown·온톨로지 저장.

| 단계 | 담당 | 동작 |
|---|---|---|
| 녹음·업로드 | 사람 | Drive 폴더 또는 POST /v1/uploads |
| 감지·다운로드 | GAS+서버 | 5분 간격 감지, 폴더/버전 확인, 중복 방지 |
| 전사 선택 | 사람/등록 설정 | 기본 groq, 정밀 검토용 gemini. 자동 공급자 전환 없음 |
| 전사 | Groq/Gemini | 원문과 타임스탬프 저장. Groq는 화자 미상 |
| 요약 | Gemini Developer | 샘플 문체와 번호 있는 원문·과거 자료를 구조화 JSON으로 정리 |
| 저장 | 서버 | 직접 인용 검증 후 SQLite에 Markdown 및 온톨로지 구성 데이터 영속 저장 |
| 검수·인덱싱 | 사람+코드 | 이름·할 일·기한·누락 검수 후 과거 검색 자료와 Soloforce corpus로 승격 |

두 공급자의 한도 초과(429)나 인증 실패(401/403)는 waiting 상태로 멈춘다. 원인 해결 후 retry API를 호출한다. 요약 실패 시 성공한 전사 checkpoint는 재사용한다. 형식·근거 오류는 최대3회 처리하며 잘못된 인용을 성공으로 저장하지 않는다.

Gemini 선택이 항상 더 정확하다는 보장은 없다. 현재 검증 모델은 gemini-2.5-flash이며 GEMINI_MODEL로 교체 가능하다. Gemini2.5Pro는 현재 계정에서404를 반환하여 기본으로 채택하지 않았다. 회의 끝부분 누락·인명·수치·화자 판단은 사람이 확인한다.

Telegram은 현재 기본 실행 흐름에서 비활성화했다. GAS date는 파일 수정일 기준이므로 실제 회의 날짜는 별도 확인한다.
