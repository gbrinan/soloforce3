# Tool Use 재설계 (싱글 기본 + 레인)

## Background

soloforce2는 상주 페르소나 30명과 오케스트레이터(genie)가 텍스트 태그·프롬프트 지시로 일을 주고받는 구조다. 2026-10-07 리뷰에서 세 가지가 드러났다. 프롬프트가 가르치는 계약이 도구 스키마에 없고(DelegateTask `model`, 위임 59건 중 사용 0건), 승인·종료 훅 스크립트 3종이 라이브에도 없으며, genie 비용 대부분이 사람 대화가 아니라 내부 조정 이벤트에서 나온다. 무엇보다 이 판단의 근거인 비용 원장이 과거 행에서 부풀어 있었다.

## Goal

정책을 프롬프트가 아니라 도구 스키마와 서버 검증에 둔다. 기본은 단일 에이전트가 도구로 일하고, 컨텍스트·권한·검증 독립성이 다른 작업(개발, 인제스트, QA)만 격리 레인으로 보낸다.

## How it works

### 단계

- Stage 0 계기판: 비용 원장을 믿을 수 있게 만든다. 이후 모든 단계의 효과를 이것으로 잰다.
- Stage 1 반증 실험: 사람이 직접 한 요청 30건을 단일 에이전트로 재실행해 사람 라벨로 비교한다.
- Stage 2 흡수: 저사용 에이전트를 `mode: skill | lane` 플래그로 몇 명씩 본체 스킬로 접는다.
- Stage 3 레인 상태 머신과 결정적 알림기.
- Stage 4 도구 등급과 지연 로딩, 훅 3종 복구, DelegateTask `tier`.

### 레인을 띄우는 기준

컨텍스트가 다르다, 권한이 다르다, 검증이 독립이어야 한다, 한 턴을 넘겨 오래 걸린다, 인젝션 위험 입력을 격리된 방에서 읽어야 한다 — 다섯 중 하나라도 해당하면 레인, 아니면 본체가 처리한다.
